# 15. Compatibility report (release 1.0.0)

Generated 2026-11-08 for PhoneBridge 1.0.0. Scope: what this release runs on,
what was **actually executed** while producing it, and what is expected but
unverified. Anything marked *unverified* is a claim about the code, not about a
machine someone ran it on.

Evidence for each row is a test file, a command, or a document section — not an
opinion.

## 3. Protocol compatibility

| Item | State |
| --- | --- |
| `PROTOCOL_VERSION` | `1`, identical in Python, Kotlin and the reference phone — asserted by `tests/test_protocol_contract.py` |
| Version skew | Refused in both directions with a terminal error (never a reconnect loop) |
| Method set | 7 RPC methods + PING/PONG + BLOB echo, three-way enforced: `docs/03` ⇔ `BridgeServer.kt` ⇔ `phone_sim.py` |
| Error codes | 7 documented codes; the contract test fails if Kotlin emits an undocumented one |
| Reserved kinds | `0x30 AUDIO`, `0x40 VIDEO`, `0x50 FILE`, `0x60 SENSOR` — numbers only, no body format, asserted absent from both implementations |
| Reserved-kind forward compatibility | An unknown kind inside an established session is logged and ignored; the session survives |
| Kotlin ↔ Python byte compatibility | Known-answer vectors generated by `tools/vectorgen` and checked from both sides (ECDH, HKDF, SAS, AES-GCM framing, envelope codec) |

## 5. What "compatible" does *not* mean here

* The reference phone in `tools/simulator/` implements the same wire protocol as
  the app and is what every end-to-end test talks to. Passing those tests proves
  the **protocol** works; it does not prove the app behaves on a handset.
* No device in this environment had a Bluetooth headset attached, so no audio
  measurement exists for any of the three target handsets
  ([`09-compat-report.md`](09-compat-report.md), all `unmeasured`).
* Battery-optimisation behaviour, Doze, and OEM foreground-service killing are
  untested by definition without a device.

## 6. Summary for the release notes

> PhoneBridge 1.0.0 has been verified on Linux with Python 3.11 against the
> reference phone implementation (575 tests, lint, type check, clean-venv install,
> CLI sweep). The Android app compiles against the protocol layer and its
> behaviour is source-audited, but **it has not been run on a physical handset by
> this project**, and the release APK must be built and installed by the user
> (`docs/14-release-readiness.md` §3). Windows users should expect to run the
> PowerShell steps in `docs/11` themselves.
